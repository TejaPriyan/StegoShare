Important Security Distinction: Steganography ≠ Encryption

Steganography hides the existence of a message inside image pixels, whereas Encryption makes the message unreadable without a cryptographic key. If you embed a message without a password, anyone using STEGOSHARE can extract it. Always enable AES-256-GCM Password Protection for sensitive communications, and always share the output image as an uncompressed document/file (avoid lossy JPEG re-encoding on social media).

        DEEP TECHNICAL ARCHITECTURE
        
How STEGOSHARE LSB & AES-256-GCM Work

        

          A transparent look inside the bit-level serialization protocol, RGB channel manipulation, key derivation, and why lossless PNG transport is essential.
        

      


      
      

        

          
1. Versioned Binary Packet Format (v1 Specification)

          Deterministic Big-Endian Serialization
        

        

          Before a single pixel is modified, STEGOSHARE constructs a self-framing binary packet so the receiver can reliably identify the exact start, metadata, cryptographic parameters, integrity checksum, and end byte without ever needing the original image:
        

        

          

            
Bytes 0..9 (10 Bytes)

            
Magic Signature

            
ASCII "STEGOSHARE". Immediate validation that the carrier holds a STEGOSHARE payload.

          

          

            
Bytes 10..11 (2 Bytes)

            
Version & Flags

            
Version 0x01 + bitmask (bit0 = Encrypted, bit1 = File Mode).

          

          

            
Variable (0 or 30 Bytes)

            
PBKDF2 Salt & GCM IV

            
16-byte random Salt + 12-byte random Nonce/IV generated via crypto.getRandomValues.

          

          

            
8 Bytes + Payload

            
Length + CRC32 + Data

            
Uint32 Payload Length + Uint32 CRC32 Checksum + UTF-8 or AES-256-GCM Ciphertext & 16B Auth Tag.

          

        

      


      
      

        

          STEP 01 • PIXEL EXTRACTION
          
RGBA Canvas Decomposition

          

            Any uploaded image (`PNG`, `JPG`, `BMP`, `WEBP`) is drawn onto an offscreen HTML5 Canvas. `ctx.getImageData(0, 0, W, H)` returns a flat `Uint8ClampedArray` where every 4 bytes represent `[R, G, B, A]` in the range `0..255`.
          

          

            Capacity = ⌊(Width × Height × 3) / 8⌋ Bytes
          

        


        

          STEP 02 • AUTHENTICATED CRYPTO
          
PBKDF2 + AES-256-GCM

          

            When password protection is enabled, the plaintext UTF-8 bytes are encrypted with `Web Crypto API`. `AES-GCM` appends a 128-bit authentication tag (`16 bytes`). If a receiver enters even 1 wrong character in the password, authentication fails cleanly and never outputs garbage bytes.
          

          

            Key = PBKDF2(Pass, Salt_128, 100000, SHA256)
          

        


        

          STEP 03 • TRANSPORT INTEGRITY
          
Why JPEG Compression Destroys LSBs

          

            Lossy formats (`JPEG`, social media re-compression on WhatsApp/Instagram/X) apply Discrete Cosine Transform (DCT) quantization, which overwrites least significant bits. Always export and transmit STEGOSHARE images as lossless PNG files or uncompressed attachments.
          

          

            Output = canvas.toDataURL('image/png')

Privacy & Security Policy

            
Zero-Knowledge Architecture • 100% Client-Side

          

        

        

          
          

            
            
          

          
        

      


      
      

        
        

          

            ✓ ZERO-KNOWLEDGE GUARANTEE: Images, passwords, encryption keys, and decoded messages never leave your browser RAM.
          

          
1. Zero Server Processing & Data Transmission

          
STEGOSHARE operates without a backend database or processing server. All steganographic pixel manipulations and AES-256-GCM cryptography execute locally inside your web browser’s JavaScript sandbox via the HTML5 Canvas API and the standard Web Crypto API (SubtleCrypto).

          
          
2. No Tracking, Telemetry, or Cookies

          
There are zero tracking scripts, Google Analytics, cookies, local storage tracking identifiers, or session beacons in STEGOSHARE. We do not log IP addresses, user agents, or file metadata.


          
3. Volatile RAM & Memory Purging

          
Pixel buffers, text messages, and derived keys reside exclusively in volatile memory (Uint8ClampedArray / Uint8Array). Clicking the "Purge Memory" button or closing the browser tab immediately frees all data from memory.


          
4. Open Source Verification

          
The complete codebase is available under the MIT License on GitHub for public inspection, audit, and verification.
